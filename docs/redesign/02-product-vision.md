# FTC2 New Product Vision — رؤية المنتج الجديد

> من: برنامج إدارة مركز تدريب بواجهة محسّنة
> إلى: **نَبْض — مركز القيادة التشغيلي والمالي لمراكز التدريب**

---

## 1. الجوهر

نبض = نبض المنشأة. المنتج يجعل المدير **يشعر بالنبض** خلال ثوانٍ من الفتح:
هل الوضع صحي؟ أين يتدفق المال؟ ما الذي يحتاج انتباهه اليوم؟

**الوعد:** كل شاشة قابلة للعرض في Demo تجاري أمام مستثمر أو مدير مالي، وكل وظيفة قائمة تبقى تعمل.

## 2. المفاهيم الحاكمة

### أ) Financial Cockpit (مركز القيادة)
الرئيسية ليست Dashboard بطاقات — بل قيادة هرمية:
Net Position ضخم → تدفق Money In/Out → Timeline نشاط حي → تنبيهات → إجراءات سريعة (4–6 فقط).

### ب) Contextual Navigation
لا sidebar بعشرات البنود. ثلاث دوامات سياقية:
- **التشغيل**: عملاء، دورات، حقائب، شركات
- **المالية**: خزنة، فواتير، مشتريات، قيود، موازنة
- **الذكاء**: تقارير، تدقيق، إعدادات
+ Command Center (Ctrl+K) يصل كل شيء من أي مكان.

### ج) Workspaces لا Forms
- العميل = Customer Workspace (بروفايل + رصيد + حركات + فواتير + Timeline في مساحة واحدة)
- الفاتورة = Document Workspace (تحرير يسار + معاينة حية يمين)
- القيد = Journal Editor مع مؤشر توازن حي (Balanced ✓ / Difference)
- المطابقة/الحركات الكبيرة = Reconciliation Workspace بأعمدة متقابلة وتقدم بصري
- التقارير = Report Studio (فترة + مقارنة + تصدير في استوديو واحد)

### د) Motion Language
سريع وغير مبالغ: 120–250ms، easing موحد، احترام prefers-reduced-motion (موجود أصلًا).

## 3. الهوية

| العنصر | القرار |
|---|---|
| الاسم | نَبْض (Nabd) — يبقى؛ هو الأصل التسويقي |
| الرمز | نبضة تخطيط قلب تتوسطها نقطة مالية — يعاد رسمه SVG نظيف |
| اللونان | كهرماني (طاقة/انتباه) + فيروزي (ثقة/مال) — يُنظمان في Tokens بدل إعادة اختراع |
| الأرقام | IBM Plex Mono دائمًا للقيم المالية (موجود، يُعمَّم) |
| الصوت | عربي أولًا، مصطلحات محاسبية دقيقة، بلا زخرفة |

## 4. لماذا سينجح تجاريًا

1. **تموضع فارغ**: برامج المحاسبة العامة لا تفهم مراكز التدريب (حقائب، جلسات، رعاية شركات، صحة تعليمية) — ونبض يفهمها
2. **الامتثال مدمج**: ZATCA جاهزة ضمن السرد
3. **الفريق**: أدوار الاستقبال المحاصرة = بيع لأكثر من مقعد
4. **العرض الأول**: Cockpit يجعل الـ Demo يبيع نفسه في 30 ثانية

## 5. الخطوط الحمراء (من brief العميل — ملزمة)

- لا كسر لوظائف أو منطق محاسبي أو Schema أو APIs أو Auth أو صلاحيات أو تقارير أو تكاملات
- فهم ← توثيق ← إعادة تصميم ← تنفيذ ← اختبار
- تزايدي لكل مرحلة: فحص ← تحديد المتأثر ← شرح ← تنفيذ ← اختبار ← تحقق من القديم
