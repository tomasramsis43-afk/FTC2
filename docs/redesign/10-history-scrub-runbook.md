# Runbook: تطهير تاريخ Git من بيانات العملاء الحقيقية

> ⚠️ **تنبيه**: هذا الإجراء يعيد كتابة التاريخ بالكامل (كل هاشات الـcommits تتغير) ويتطلب
> force push. لا يُنفَّذ إلا بموافقة صريحة، وبعد نسخة احتياطية كاملة. أي نسخة عمل (clone)
> قديمة لدى أي شخص ستفقد صلتها بالمستودع ويلزم استنساخها من جديد.

## الخيار الموصى به — مستودع جديد نظيف (ضمانة مطلقة)

يحذف المستودع القديم كلياً من GitHub فتختفي معه الكائنات المعلقة التي قد يُبقيها
GitHub خلف الكواليس بعد أي rewrite داخلي:

1. نسخة احتياطية محلية كاملة (بالتاريخ القديم) للرجوع عند الحاجة:
   ```powershell
   git bundle create "$env:USERPROFILE\Desktop\ftc2-history-backup.bundle" --all
   ```
2. إنشاء مستودع جديد فارغ على GitHub باسم جديد مؤقتاً (مثلاً `nabd`) **دون** README تلقائي.
3. زرع الجذر عند لجنة التنظيف وحذف كل ما قبلها من التاريخ المحلي:
   ```powershell
   pip install git-filter-repo
   git replace --graft 72e6615          # يجعل Phase 0 جذراً بلا آباء
   git filter-repo --force              # يخبّر الاستبدال ويعيد كتابة الهواشات
   # filter-repo يحذف remote احتياطياً — أعِده نحو المستودع الجديد:
   git remote add origin https://github.com/<account>/nabd.git
   git push -u origin main --tags
   ```
4. تحديث المستودع المصدر في Render للمستودع الجديد (أو أبقِ نفس اسم المستودع: أنشئ
   `nabd` ثم احذف القديم ثم أعد تسمية `nabd` إلى `FTC2`).
5. تحقق نهائي على النسخة المستنسخة الجديدة:
   ```powershell
   git clone https://github.com/<account>/nabd.git ..\nabd-check
   # ثم مسح كل الالتزامات:
   git rev-list --all -- frontend/app.html | ForEach-Object {
     $c = git show "$_:frontend/app.html" 2>$null | Out-String
     if($c -and [regex]::Matches($c,'\b[12]\d{9}\b').Count -gt 0){ "متبقي في $_" }
   }
   ```
6. حذف المستودع القديم من GitHub (Settings → Delete). للتأكد الأقصى من عدم بقاء
   كائنات معلقة يمكن مراسلة GitHub Support طلباً بتشغيل gc يدوي — لكن حذف المستودع
   يغني عنها عملياً في مشروع فردي.

## البديل — نفس المستودع مع rewrite وforce push

نفس خطوات 1 و3 أعلاه، ثم بدل الخطوات 2-4:
```powershell
git push --force origin main
git push --force origin v1.0.0   # التاج أعيد توليده بهاش جديد تلقائياً
```
عيبه: GitHub قد يُبقي الكائنات القديمة متاحة بهاشاتها المباشرة حتى تشغيل gc لديهم
(تُطلب عبر Support)، وأي fork قديم يحتفظ بالبيانات. مقبول فقط إذا كان المستودع
فردياً بلا forks ولا يهمك الاحتمال النظري.

## بعد أي خيار
- أي جهاز/استضافة تسحب من المستودع (Render) تعمل من جديد تلقائياً بعد الضبط.
- لا تفقد أي شيء من العمل: كل المراحل 0→7 وسجل CHANGELOG والوثائق تبدأ من `72e6615`.
- احتفظ بملف الـbundle الاحتياطي في مكان آمن **مشفَّر** — فهو يحوي التاريخ القديم عمداً.
