# FTC2 Navigation + Dashboard Concepts

---

## الجزء الأول: Navigation Concept — التنقل السياقي

### المشكلة الحالية
13 تبويبًا مسطحًا في sidebar واحد. المستخدم الجديد لا يبني خريطة ذهنية، والمتقدم يضيع بين التبويبات.

### الحل: Domain Switcher + Contextual Rail

```
┌─────────────────────────────────────────────────┐
│ Header: نبض · الشركة · الفترة · بحث Ctrl+K · مستخدم │
├──────┬──────────────────────────────────────────┤
│ Rail │                                          │
│ 🏠   │        مساحة العمل الحالية               │
│ 👥   │   (شريط أدوات سياقي يتغير حسب الدوامة)   │
│ 💰   │                                          │
│ 📊   │                                          │
│ ⚙️   │                                          │
└──────┴──────────────────────────────────────────┘
```

1. **Rail أيقوني رفيع (64px)** بدل sidebar عريض: 5 مداخل فقط
   - الرئيسية (Cockpit)
   - التشغيل → عملاء / دورات / حقائب / شركات
   - المالية → خزنة / فواتير الدورات / مشتريات / القيود / الموازنة
   - الذكاء → تقارير / تدقيق
   - الإعدادات (تنقل من قائمة المستخدم إلى هنا)
2. **النقر على دومين يفتح Drawer/Popover** بأدواته الفرعية — الوظائف تظهر بسياقها
3. **التبويب النشط داخل الدومين** يظهر كشريط أدوات أفقي أعلى المحتوى (contextual tabs)
4. **توافق كامل**: كل view موجود يبقى بمساره؛ التغيير في طبقة التنقل فقط (`nav.tabs` تُعاد هيكلتها بصريًا دون تغيير `data-view` أو dispatch table في undo-redo.js)
5. **اختصارات Alt+1..9 تبقى** وتُوسَّع لاحقًا

### Command Center (Ctrl+K)
البحث الشامل الحالي **مكسور** (عناصره غير موجودة). نبنيه صحيحًا:

- Overlay مركزي بنتائج مصنفة: عملاء · فواتير · قيود · حسابات · تقارير · إعدادات · **أوامر**
- الأوامر: «إنشاء فاتورة»، «فتح كشف عميل»، «القيود غير المتوازنة»، «مطابقة بنكية»، «تقرير الأرباح»...
- بحث محلي فوري في المصفوفات الحية (clients, vaultTx, manualSalesInvoices, accounts...) — بلا طلبات شبكة إضافية
- لوحة المفاتيح أولًا: أسهم للتنقل، Enter للتنفيذ، Esc للإغلاق
- يستبدل زر البحث الحالي بنفس الموضع ونفس الاختصار (Ctrl+K) — ترقية شفافة

## الجزء الثاني: Dashboard Concept — مركز القيادة (Financial Cockpit)

### الهيكل الهرمي (من الأكبر للأصغر)

```
┌────────────────────────────────────────────────────────┐
│ Financial Pulse                                        │
│ صافي المركز الآن        مقارنة بالفترة السابقة ▲ 12.4%  │
│ ┌──────────────┬──────────────┬──────────────┐         │
│ │ الخزنة       │ الشبكة/البنك │ الذمم المستحقة│         │
│ └──────────────┴──────────────┴──────────────┘         │
├──────────────────────────────┬─────────────────────────┤
│ Money Flow (آخر 30 يومًا)     │ Alerts                  │
│ In ▓▓▓▓▓▓ Out ▓▓▓ Net ▓▓      │ · فاتورة غير مرحّلة      │
│ sparkline + net flow          │ · حقيبة تحت الصفر        │
│                              │ · موازنة انحراف 4%       │
├──────────────────────────────┼─────────────────────────┤
│ Activity Stream (Timeline)    │ Quick Actions (4–6)      │
│ 09:41 تسجيل فاتورة بيع        │ [تسجيل متدرب]            │
│ 09:38 تحصيل دفعة             │ [قبض/صرف]                │
│ 09:22 إنشاء قيد              │ [فاتورة دورة]            │
│ 09:05 مطابقة عملية           │ [قيد يومية]              │
└──────────────────────────────┴─────────────────────────┘
```

### مصادر البيانات — كلها موجودة اليوم (لا Backend جديد)
| العنصر | المصدر |
|---|---|
| Net Position | vaultTx + أرصدة الشبكة (منطق renderVault/renderDashboard الحالي) |
| Receivables | حسابات العملاء غير المسددة (clients[].paid vs price) |
| Money Flow | تجميع vaultTx by type/date |
| Alerts | قواعد clients-alerts-overview.js الحالية + قيود غير متوازنة + مخزون حقائب سالب |
| Activity Stream | auditLog (موجود وشامل!) — آخر N عملية بصيغة Timeline |
| Quick Actions | نفس دوال الفتح الحالية (openClientModal, vault movement form...) |

### التخصيص (Personalization)
- كل widget قابل: إخفاء / ترتيب / حجم (S/M/L)
- Layout يُحفظ per-user في settings الحالية (localStorage→server sync موجود)
- Reset إلى التخطيط الافتراضي

### قواعد صارمة
- لا بطاقات متشابهة متكررة — كل منطقة لها لغة بصرية مختلفة (رقم ضخم / مخطط / خط زمني / قائمة تنبيهات)
- كل رقم مقارَن يحمل Trend indicator ▲▼%
- Skeleton states أثناء أول تحميل، Empty state موصوف إذا لا بيانات
- الأداء: تجميع واحد للحسابات في الذاكرة (لا عشرات الطلبات)، الرسم CSS/sparkline خفيف
